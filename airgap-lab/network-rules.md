# Air-gap lab network rules

These rules describe the security-group/VM boundary around the nftables gate.
They are intentionally narrower than the connected defaults in
`suse-ai-stack`. Security groups are allow-lists, not proof by themselves; the
lab's host-output and pod-forward rules plus negative probes provide the active
deny assertion.

## Required private flows

| Source | Destination | Protocol/port | Purpose |
|---|---|---:|---|
| seed/controller | all lab VMs | TCP 22 | Ansible during setup and evidence collection |
| management/workload nodes and pods | services VM | TCP 443 | Harbor; also Gitea when private-CA HTTPS is selected |
| management/workload nodes and pods | services VM | TCP 30030 | Gitea authenticated HTTP baseline only |
| downstream nodes/agents | Rancher private address | TCP 443 | Rancher registration, Fleet and cluster-agent callbacks |
| isolated browser | Rancher private address | TCP 443 | UI journey |
| lab nodes/pods | internal DNS resolver | UDP/TCP 53 | Name resolution without public transport |
| lab nodes | internal NTP source | UDP 123 | Certificate and Kubernetes clock correctness |
| RKE2 servers/agents | peers in the same cluster | RKE2/CNI ports | Preserve the provider-specific RKE2 rule set |

For the default RKE2/Canal layout, the peer rule set normally includes TCP
`9345`, `6443`, `10250`, server-only etcd TCP `2379-2381`, and Canal VXLAN UDP
`8472`. Do not copy this list blindly if the stack selects another CNI or an
external load balancer; retain the exact RKE2 rules already generated by the
base environment.

Harbor and Gitea accept traffic only from the seed and lab-private security
groups. They are not configured as pull-through or Git proxy services. Gitea's
SSH service is not exposed in this first-pass lab.

## Connected-to-isolated transition

1. The seed and services VM may use public egress while RKE2, Harbor, Gitea and
   the artifact bundle are built.
2. Management and downstream clusters may use public egress only while the base
   Rancher/RKE2 stack is provisioned and cached system images are present.
3. Configure the lab CA, private names, RKE2 mirrors, and
   `disable-default-registry-endpoint` before removing egress.
4. Remove `0.0.0.0/0` and `::/0` egress from the management, workload, and
   browser security groups when practical, then run the `isolate` phase.
5. Install AIF only after the gate is active. The services VM may remain
   connected for this first pass because neither service proxies upstream.

On AWS, use private instance addresses and a controller inside the VPC (or an
SSH bastion). Prefer security-group references between roles. A stricter
qualification VPC has no NAT/Internet Gateway route for isolated subnets and
uses VPC Flow Logs to corroborate the host/pod probes. The current stack's
public IPs, Internet Gateway and open egress are connected-stage conveniences,
not the final isolation boundary.

## Fail-closed requirements

- Do not put an HTTP(S) egress proxy inside an allowed private CIDR. Clear proxy
  variables and RKE2/containerd proxy drop-ins on isolated nodes unless the
  proxy itself enforces an equivalent deny policy.
- Do not allow the AWS metadata endpoint (`169.254.169.254`). The example allows
  only the VPC DNS resolver (`169.254.169.253`) on port 53.
- Do not add a default route to `airgap_allowed_*_cidrs` or add the services VM
  to `airgap_isolated` until its own RKE2/Harbor/Gitea artifacts are mirrored.
- List every schedulable node in `rke2_airgap_nodes` and `airgap_isolated`.
  Configuring only a control plane leaves worker pulls and pod egress untested.
- Keep the seed out of the isolated allow-list after media transfer. Its
  continued reachability must not become an application dependency.

The `verify` phase records nftables counters and rejects a new public TCP
connection from every isolated host and a scheduled pod while requiring Harbor
and Gitea to stay reachable. For AWS runs, archive matching rejected/absent VPC
Flow Log records with the playbook evidence.
